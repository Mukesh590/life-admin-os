# Reference Design DNA — 7-Image Synthesis

## Method note

Per `image-to-code` skill discipline: each image was read directly (not generated by me — these are user-supplied references, so the skill's "generate first" step doesn't apply here; I went straight to the deep-analysis and extraction passes) and put through the same five-part extraction: text, typography, spacing, component/button, color. Per-image findings are below; the synthesis section after that is what's actually usable as a shared design system. IMG_4371 was excluded from the synthesis — see the Outlier section at the end for why.

## Synthesized Shared DNA

### 1. Background treatment — light off-white range
All 7 backgrounds sit in a narrow near-white band, never a flat pure white and never a saturated color: `#EAEDF0`, `#F4F4F4`, `#F8FBF8`, `#FDFCFA`, `#FAF5EF`, `#F4F8FF`, `#FDFFF5`. Each has a faint temperature tint — cool gray-blue (OPPO, duyu, Kawasaki), warm cream (POC, MDXLAB), neutral gray (VIBRAM), cool mint-white (Segai) — but none is a saturated brand color and none is true `#FFFFFF`. The tint appears to key off each brand's accent hue (Kawasaki's bg carries a whisper of its lime accent; duyu's carries a whisper of its teal). **Rule for implementation:** pick an off-white 2–4% off pure white, tinted very slightly toward whatever the single accent color will be, never a flat `#FFFFFF` or a neutral `#F5F5F5` disconnected from the accent.

### 2. Typography approach — oversized bold display type as hero
Every one of the 7 uses a single, massive, bold, all-caps display headline as the dominant visual element of the hero — never a modest heading with a big image doing the work. Three sub-patterns recur:
- **Overlap-with-product** (VIBRAM, POC, Kawasaki): the product photo directly masks/overlaps the headline letters. This is a deliberate, repeated motif — not noise to clean up in implementation.
- **Centered restraint** (Segai, duyu): headline centered, 1–2 lines, generous surrounding whitespace, no image overlap.
- **Techno/experimental face** (MDXLAB, Kawasaki): a distinctive geometric/angular display font used specifically for tech-forward products, breaking from the plainer grotesks used by the lifestyle/wellness refs.
Across all 7, headline tracking is tight-to-normal (never loose), subheads are dramatically smaller (roughly 4–5% the visual weight of the headline) and set in a plain regular-weight sans — the contrast ratio between hero type and body type is extreme by design.

### 3. Restraint pattern — one accent color, minimal chrome
Five of the seven (OPPO/periwinkle, VIBRAM/orange, Segai/pink, duyu/teal, Kawasaki/lime) commit to exactly one accent hue, used sparingly — on a single CTA, a nav pill, a product highlight, or a tag chip — while everything else in the frame is pure black/near-black text on the off-white ground. Two (MDXLAB, POC) push restraint to its logical extreme and use **zero** hue accent at all — pure black-on-off-white monochrome. None of the 7 uses more than one accent color simultaneously. Chrome is minimal everywhere: a nav bar, one headline, one CTA, and at most one secondary content block (a caption, a video thumbnail, a tag pair) — never dashboard-style card stacks or multi-widget layouts. Buttons are almost universally pill-shaped (`rounded-full`); the one exception (VIBRAM's "ADD TO CART") is a plain rectangle rendered in black specifically to outrank the accent color in the CTA hierarchy.

### 4. Animation implication — cinematic entrance, scroll reveals
Nothing in these images is literally animated (they're static screenshots), but several visual choices strongly imply a specific motion language if built:
- The **overlap-with-product** motif (VIBRAM, POC, Kawasaki) implies the product renders should cinematically slide/fade into place *behind or through* the headline on load — a staged reveal where type and hero image resolve together, not two independently-animated blocks.
- The **centered, generous-whitespace** heroes (Segai, duyu) imply a calm fade-up entrance: headline, then subhead, then CTA, staggered — nothing needs to be fast or busy given how much negative space these compositions are built around.
- duyu's edge-to-edge marquee strip implies a perpetual, slow infinite horizontal scroll — the one place in the set where continuous (not one-shot) motion is implied.
- The tiny tracked eyebrow labels (OPPO's "A perfect...", Kawasaki's "KAWASAKI," Segai's nav labels) and vertical side labels (POC's, Kawasaki's) are exactly the kind of small secondary element that reads as a natural candidate for a subtle scroll-triggered fade/slide-in reveal, distinct from and secondary to the hero's own entrance.
Overall implication: a single deliberate hero entrance (not a bouncy or high-energy one — these designs are calm and restrained), followed by scroll-triggered reveals for secondary content blocks as the user scrolls past the fold. Nothing in the reference set implies scrubbed/pinned scroll effects or heavy parallax — the restraint pattern (rule 3) extends to the implied motion as well.

## Outlier: IMG_4371 (excluded from synthesis)

This image is a dark "Glassmorphism" fintech dashboard mockup (labeled as such at the bottom of the frame, itself a category/style tag rather than site content) — a photographic dark background (blurred bookshelf/lantern scene), heavy translucent glass cards, and a dense multi-widget layout (balance strip, chart, transaction list, goals, savings, a gradient VISA card). It uses **two** simultaneous accents (orange primary, teal secondary) plus a gradient card treatment, and its chrome density is the opposite of minimal — five-plus distinct widget blocks visible at once.

None of the four synthesized traits above hold for this image: its background is dark and photographic, not light off-white; there's no oversized bold display headline (the largest text, "My Dashboard," is a modest heading); it uses multiple accents rather than one; and its dense card-grid implies a very different motion language (staggered widget entrances, not a single cinematic hero reveal). I've kept it out of the synthesis rather than diluting the other 7's clear shared pattern to accommodate it. If it's meant to inform a *different* part of the product (e.g., an actual data-dense dashboard view, as opposed to a marketing/landing hero), it's worth treating as a separate reference set rather than merging it here.
